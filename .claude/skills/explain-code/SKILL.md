# Explain Code

When explaining code, always include:

1. **Start with an analogy** — compare the code to something from everyday life (a kitchen, a post office, a library, a conveyor belt).
2. **Draw a diagram** — use ASCII art to show the flow, structure, or relationships between parts.
3. **Walk through the code** — explain step by step what happens, in the order it runs.
4. **Highlight a gotcha** — name one common mistake or misconception.

Keep explanations conversational. For complex concepts, use several analogies, one per layer.
Avoid jargon; when a technical term is unavoidable, define it in one plain sentence.
Answer in the user's language.
