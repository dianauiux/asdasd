## 1 · Tue 10.11 · "Which design system is it reading?"

**Hooks**
1. Figma's agent can now draw on the canvas. My first question wasn't "how good is it?" It was "what is it reading?" ✓
2. An agent will follow your design system perfectly. That's the scary part.
3. Agents don't guess your rules. They follow the ones you wrote down.

```
Figma's agent can now draw on the canvas. My first question wasn't "how good is it?"

It was "what is it reading?"

An agent works from what's written down: the components, the tokens, the guidelines in the library. It doesn't know that "we never put two primary buttons on one screen" unless someone wrote that down somewhere.

On most teams I've seen, the real design system lives in a few people's heads. The Figma library is the part someone had time to document.

A human designer fills those gaps by asking around. An agent fills them with something that looks right.

So the first real AI project for a design team isn't a prompt. It's writing down the rules you've been saying out loud for two years.

If an agent opened your design system today, what would it get wrong first?

Save this for your next design system review.

#ProductDesign #DesignSystems #AIDesign #Figma
```

## 2 · Fri 13.11 · "The brief I write before an agent touches a file"

**Hooks**
1. I don't let an agent touch a file before it gets these 5 lines. ✓
2. The shortest brief I write is for an AI agent. It's also the strictest.
3. Prompting an agent is just writing a good design brief.

```
I don't let an agent touch a design file before it gets these 5 lines:

1. Who is this for?
One sentence about the user and the moment they're in. "A first-time user on their phone, trying to send money before their bus arrives."

2. What must not change?
The things you'd be upset to see moved: navigation, brand color, the checkout order.

3. What can it use?
Which library, which components. "Only components from the published library. No new styles."

4. What does done look like?
"Three options for the empty state. Each one fits on one mobile screen."

5. When should it stop and ask?
"If you need a component that doesn't exist, stop and list it. Don't invent one."

None of this is new. It's the brief a good junior designer gets on day one. The difference is that a junior will ask when something is missing. An agent won't.

Copy this and keep it next to your prompts.

Which line would you add as number 6?

#AIDesign #ProductDesign #UXDesign #DesignProcess
```

## 3 · Tue 17.11 · "Who trains the next senior designer?"

**Hooks**
1. Agents are taking the tasks junior designers used to learn on. Nobody has a plan for that. ✓
2. Resizing, variants, redlines. Boring work. Also the way most of us learned.
3. If agents do the junior work, where do seniors come from?

```
Agents are now doing the tasks junior designers used to learn on.

Resizing frames for five screen sizes. Building every state of a component. Redlines for developers. Renaming 300 layers.

Nobody misses that work. But that work taught people things. You learn spacing by fixing spacing a hundred times. You understand a component when you've built all twelve states yourself.

I see this with my students at Pixel Academy. The ones who grow fastest still do some of the boring work by hand, at least once, before they let a tool do it.

So the question for design leads isn't "how many juniors can agents replace?" It's "how will our juniors still get the reps?"

Some ideas: let juniors review the agent's output instead of skipping that step. Pair them on the decisions, not only the production. Give them one feature to build by hand every quarter.

The industry will still need senior designers in five years. They have to come from somewhere.

Design leads: how are juniors learning on your team now?

#DesignLeadership #UXDesign #AIDesign #DesignCareers
```

## 4 · Fri 20.11 · "3 things I check before a team adds an agent"

**Hooks**
1. Before a product team adds an AI agent to their design workflow, I check 3 things. ✓
2. Your team wants design agents. Is your product ready for them?
3. The agent is the easy part.

```
Before a product team adds an AI agent to their design workflow, I check 3 things.

1. Is the library the real source of truth?
If developers use one set of components and Figma has another, the agent will make screens nobody can ship.

2. Are the rules written next to the components?
"Use this for destructive actions only." "Max one per screen." Agents follow guidelines like these when they're in the library. They ignore the ones that live in Slack threads.

3. Does someone own the output?
An agent can make 20 screens in a minute. Someone still has to decide which 2 are right for your users, and say no to the other 18.

If all three are in place, agents save a team real time. If not, they make more of the same problems, faster.

This is a big part of what I do with product teams in AI, fintech and SaaS: get the foundation ready so new tools help instead of adding noise.

If your team is thinking about this, my inbox is open, or start at deedesign.me.
```
